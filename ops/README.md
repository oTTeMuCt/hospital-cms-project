# Эксплуатация Hospital CMS

## Доступ через HTTPS

Для рабочего сервера нужен домен, указывающий на сервер, доступные порты 80 и 443, а также Docker Compose 2.24.4 или новее. Заполните защищённый файл .env на сервере. Укажите HCMS_DOMAIN, случайные DJANGO_SECRET_KEY, POSTGRES_PASSWORD и GRAFANA_ADMIN_PASSWORD. Если используете DATABASE_URL, укажите тот же пароль и нужный сервер БД. Перед подключением пользователей создайте для каждого отдельную учётную запись в разделе «Сотрудники». Проверьте, что ни у кого нет общей демо-учётной записи.

На Linux или в WSL запустите:

```bash
export COMPOSE_FILE=docker-compose.yml:docker-compose.production.yml
docker compose up -d --build gateway backend frontend celery_worker prometheus grafana
```

Пользователи открывают HTTPS-адрес домена. БД, Redis, Prometheus и Django доступны внутри сети Docker. Grafana слушает только loopback хоста. Для удалённой работы с Grafana используйте защищённое подключение к серверу. Проверка готовности Django учитывает доступ к базе и кэшу. В Prometheus настроено правило, которое показывает тревогу при недоступности метрик Django. Для уведомления дежурного об этой тревоге подключите Alertmanager или канал уведомлений Grafana.

## Почта и Telegram

Укажите EMAIL_HOST, EMAIL_PORT, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD, DEFAULT_FROM_EMAIL и режим TLS, требуемый почтовым сервером. С тестовой учётной записью запросите сброс пароля, откройте письмо и войдите с новым паролем. Затем отправьте тестовое уведомление через API и проверьте получение и статус записи.

Для Telegram укажите новый TELEGRAM_BOT_TOKEN и отдельный случайный BOT_API_KEY. Запустите `docker compose up -d bot celery_worker`. Привяжите тестовый аккаунт одноразовым кодом, отправьте тестовое уведомление, отпишитесь и проверьте прекращение доставки. Все проверки выполняйте на вымышленных данных.

## Резервное копирование и восстановление

Для согласованной копии базы и вложений выберите окно обслуживания. Остановите сервисы с записью в БД, оставив PostgreSQL доступным. Подставьте свой каталог на защищённом носителе. Путь должен указывать на новый каталог, родительский каталог должен существовать.

```bash
docker compose stop gateway frontend backend celery_worker bot
bash ops/backup.sh /mnt/encrypted-backups/hospital-cms-2026-11-27
bash ops/verify-backup.sh /mnt/encrypted-backups/hospital-cms-2026-11-27
docker compose up -d gateway backend frontend celery_worker
```

Если бот использовался до остановки, запустите его снова. Проверка считывает контрольные суммы и разворачивает базу и вложения в отдельном контейнере без сети. Для проверки перед вводом в эксплуатацию поднимите отдельный экземпляр сайта из восстановленной копии и убедитесь, что нужная карточка и вложение открываются. Храните резервные копии отдельно от рабочего сервера, включите шифрование и назначьте ответственного за регулярные проверки.

## Пробный рабочий день

На тестовых данных администратор создаёт сотрудников, главврач добавляет вид анализа и рабочий график врача. Пациент выбирает свободный интервал, регистратор переносит и подтверждает приём. Врач ведёт медкарту, прикладывает файл и назначает анализ. Лаборант вводит показатели, врач проверяет и отправляет результат, пациент видит его в кабинете. Главврач проверяет сводку по датам и выгружает отчёт. Убедитесь, что каждая роль видит только разрешённые ей данные.
